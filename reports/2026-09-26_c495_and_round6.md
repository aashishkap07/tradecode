## 2. The shadow's empty hours

**Found, proven and fixed.**

The shadow's model uses a feature called `btc4`: Bitcoin's own 4-hour move,
**copied identically to all 40 coins**. Before scoring, each feature is
rescaled by how much it varies from coin to coin. A feature that is the same
for every coin varies by zero, and **zero divided by zero is "blank"**. A
blank input meant no coin could be scored.

On the last 24 real hours of Bitget data, with the old code:
- **19 hours:** `btc4` was blank for every coin, so 0 coins were scored. This
  matches your server's log hour for hour.
- **5 hours:** a tiny floating-point rounding residue turned it into **random
  noise** instead, so those hours were scored, but on a corrupted input.

**The fix:** a feature that is the same for every coin tells you nothing about
which coin will do better, so it now counts as **0**. After the fix, **all 24
hours score 37–39 coins.** One smaller hole was fixed at the same time: a
single coin's infinite value (RARE's funding reading on 25 Sep) used to blank
a feature for every coin; now it only blanks that coin.

**The C489 research code had the identical bug.** It is fixed the same way, so
the bot and the research stay identical. The research's verdict (this engine
loses after costs) is not expected to change: it lost because it trades 4–9
times a day, and scoring more hours adds costs in the same proportion.
Re-running it is noted as optional pending task #12.

**Also:** Bitget's taker-flow data exists for only 15 of the top 40 coins, so
the shadow will stay on its "no-flow" model permanently. That is fine: both
models fail in research.
