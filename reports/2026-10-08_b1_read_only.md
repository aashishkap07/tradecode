# B1: the bot can now read your real Delta and Pi42 accounts (read-only)

8 Oct 2026. Build step B1 of the March plan (`reports/2026-10-04_live_march_roadmap.md`).

## 1. What this is, in one picture

Until now the bot only knew its **paper** accounts. From C540 it can also **look at your real accounts**
on Delta Exchange India and Pi42: your balance, open positions, the rent paid and received, and recent
trades. It shows them beside the paper ledger.

**Analogy:** a CCTV camera in your shop. It sees the shelves and the till, but it has no hands. It cannot
sell, buy or open the till.

**What the code can do:**
- **One kind of request:** an HTTP **GET**, which only asks for information.
- **Four questions per exchange, and nothing else:** the balance, the open positions, the trades, the
  money movements.
- Any other request (place an order, cancel, change margin or leverage, close a position) is refused
  inside the bot before it leaves your server. The test proves it.
- **Live trading stays locked** (`C488_LIVE_OK = False`). Nothing in this version can place an order.

**Your keys:**
- They live only in `data/api_keys.json` on your server, readable by you alone (chmod 600).
- They are never in the code, never in a log line, never on the page, never in chat.
- The hourly log upload already blanks anything labelled like a key. It now also blanks **every value in
  that file by its exact text**, old compressed logs included. If one survived, it refuses to upload.
- A small helper asks for the key with **hidden typing**. Nothing appears on screen or in your command
  history.

**On the page:**
- One line under **Your two accounts**: either "not connected yet", or "Your real accounts (read-only):
  Delta India USD … · Pi42 ₹… · Nothing is traded with real money yet."
- The full detail in **Your plan in detail → Your real exchange accounts**.
- The log gets one plain line per exchange, once an hour.
- The accounts are read every 10 minutes.

## 2. One thing Delta's own documentation says

Delta offers two key permissions: **"Read Data"** and **"Trading"**. Its troubleshooting page says:
"Market data: requires Read Data permissions only. **Orders, Positions, Wallets: requires Trading
permission.**"

So a Read Data key **may not be allowed to see your balance and positions**. My suggestion:

1. **Create a Read Data key first** (below). If Delta lets it read your wallet, you're done.
2. **If it can't,** the page will say exactly that: "the key works but may not read wallets or positions
   -- Delta's own docs say that needs the 'Trading' permission". You then have two safe choices:
   - **wait until mid-December** (B3, the dry run). That step must read your positions every hour anyway,
     so it needs that key then;
   - **or make a key with Trading ticked now, locked to your server's IP address.** Delta only issues
     Trading keys with an IP lock. Delta's API has no withdrawal function at all. This version of the bot
     has no order code at all.

I'd take the first option unless you want the balance check working now.

## 3. Step by step: making the keys

**Before you start:**
- Have Termius open on your server, and the exchange's website open on your phone or computer.
- **Never paste a key or secret into chat, a screenshot or the dashboard.** Only into the helper on the
  server, in step 3.

### Step 1: your server's address (once)

In Termius:

```
curl -4 -s https://api.ipify.org; echo
```

It prints four numbers with dots, for example `203.0.113.45`. Write it down: this is the address each key
will be locked to. **Analogy:** a key that only turns in one door.

Also check the server's clock. Delta refuses requests more than 5 seconds off:

```
timedatectl | grep -i synchronized
```

It should say `System clock synchronized: yes`.

### Step 2a: Delta Exchange India

1. Log in at `india.delta.exchange`.
2. Open your profile → **API Keys** (API Management) → **Create new API key**.
3. Name: `omega-read`.
4. Permissions: tick **Read Data** only. Leave **Trading** unticked.
5. If it asks for whitelisted IPs, enter the address from step 1.
6. It shows the **API key** and the **API secret** once. Keep that screen open for step 3.

### Step 2b: Pi42

1. Log in at `pi42.com`.
2. Open your profile/settings → **API Management** → **Create API key**.
3. Name: `omega-read`.
4. Leave **trading permission off**. The bot only reads.
5. Add the address from step 1 to the key's **allowed IPs**.
6. It shows the **API key** and the **secret** once. The secret is never shown again.

### Step 3: put each key on the server, without showing it

In Termius, one exchange at a time:

```
sudo -u omega bash /home/omega/omega/deploy/omega-keys.sh delta_india
```

1. It asks for the API key: paste it and press Enter. **Nothing appears on screen; that is normal.**
2. It asks for the secret: paste it and press Enter.
3. It answers only "saved delta_india: key N characters, secret M characters … (chmod 600)".

Then the same for Pi42:

```
sudo -u omega bash /home/omega/omega/deploy/omega-keys.sh pi42
```

**You don't need to restart.** The bot re-reads the file every 10 minutes. Within 10 minutes the page shows
your real balances, and the log gets a line starting `C540 real account (read-only)`.

### Step 4: check it

```
sudo -u omega bash -c 'grep -h "C540" "$(ls -t /home/omega/omega/omega_detail_*.log | head -1)" | tail -5 | cut -c1-300'
```

(C543 correction, 9 Oct: the system journal only receives warnings, so a successful read never appears there. This command reads the bot's detail log, where every read is written. The bot reads every 10 minutes and logs each exchange once an hour, so the line can be up to an hour old.)

**What a good result looks like:**
- `Delta India: USD … , 0 position(s) … nothing is traded live`.
- `Pi42: INR … , 0 position(s) …`.
- Zero positions is right: you hold no real positions until the February pilot.

**If a line starts with ⚠️**, it says in words what to fix:

| message | what to do |
|---|---|
| "may not read wallets or positions … 'Trading' permission" | Section 2 above |
| "the server's IP address is not on this key's allowed list" | Add the address from step 1 to the key |
| "the server's clock is off" | Run `sudo timedatectl set-ntp true` |
| "does not know this key" or "refused the key" | A typo or a deleted key: run step 3 again |
| "firewall answered instead of its API" | The exchange is blocking that network. Tell me; your server already reaches Pi42 for its coin list |
